# Єдині навчальні сесії (V12)

Міграція запускається Flyway при наступному запуску оновленого сервера.
Перед оновленням робочої БД збережіть резервну копію. V12 переносить:
- study_sessions → заплановані сесії AUTO;
- time_entries → RUNNING або COMPLETED зі збереженням UUID, часу та хвилин;
- tasks.scheduled_start/end → заплановані ручні сесії MANUAL.

Після перевірки кількості записів time_entries та часові колонки tasks видаляються.
Стара оцінка не підміняє факт: прострочені блоки та блоки завершених завдань
переносяться як SKIPPED, а фактичні записи — незалежно від старих планів.
Історичний зв’язок плану й факту не вгадується.

study_sessions: id, user_id, task_id, starts_at, ends_at, minutes, status, source,
created_at. Стани — PLANNED, RUNNING, COMPLETED, SKIPPED. Джерела — AUTO,
MANUAL, TIMER. PLANNED/SKIPPED містять часові межі та не містять фактичних
хвилин; RUNNING має лише фактичний початок; COMPLETED має фактичні межі й minutes.
Складений FK (task_id,user_id) забезпечує належність сесії власнику завдання.
Для користувача допускається лише один активний таймер.

При запуску таймера завдання використовується його найближча поточна або
майбутня запланована сесія. Її UUID зберігається, початок замінюється фактичним,
а статус стає RUNNING. Якщо відповідного плану немає — створюється нова сесія.
Зупинка записує фактичне завершення й хвилини в той самий запис. Початковий
план окремо не зберігається. Новий запуск після зупинки — новий підхід.

Ручне внесення хвилин використовує першу заплановану сесію завдання на обраний
день або створює нову. Введена дата й хвилини не підтверджують точну годину
роботи: ручні записи не беруть участі в аналізі звичних годин навчання.
Позначення завдання DONE зупиняє активний таймер і закриває решту планів як
SKIPPED, але не зараховує заплановані хвилини як фактичні.

Перепланування працює лише з автоматичними PLANNED-сесіями. COMPLETED і RUNNING
захищені від такого редагування. Прогноз використовує лише завершені сесії.
У тижневому календарі фактична робота позначена «Виконано», активна — «Таймер».
Нагадування про майбутні заняття не створюються для вже активних чи завершених сесій.

Перевірки: перенесення записів V11→V12, незмінність UUID при переході план→факт,
фактичні хвилини в прогнозі, збереження історії при переплануванні, власники,
конкурентний таймер і загальні регресійні тести. Робочу БД вручну не мігрували.
